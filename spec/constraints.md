# Constraints

Constraints override every other file. Each has a reason, so the rule is not relaxed when it becomes inconvenient, and a check.

| ID | Constraint | Reason | Check | Source |
|---|---|---|---|---|
| C1 | Use WordPress public APIs. Import only what `api-allowlist.md` names. | The plugin must survive WordPress updates and prove the public surface is enough. | ESLint `no-restricted-imports` generated from the allowlist. | `[U]` |
| C2 | No private API (`privateApis`, `unlock`, lock/unlock packages) anywhere except `src/adapter/private.js`. That file starts empty; adding to it requires an entry in `open-questions.md` first. | One place to change when an API moves or becomes public. | ESLint rule forbidding `unlock(` and `privateApis` outside that file. | `[B8]` `[U]` |
| C3 | `__experimental*` and `__unstable*` exports are used only through `src/adapter/experimental.js`, and only the ones `api-allowlist.md` marks experimental. | Same reason as C2; these can change without notice. | ESLint rule forbidding identifiers with those prefixes outside that file. | `[N]` |
| C4 | Build the UI from the WordPress Design System: `@wordpress/ui` first, `@wordpress/components` where `@wordpress/ui` has no equivalent, `@wordpress/icons` for every icon, `--wpds-*` tokens for every colour, space, radius, size and type value. No hand-built controls. One exception: the resize handle on the bottom edge of a browser's window (D56) is a plain element with the resize pointer, not a design-system control. | "We do not invent UI. We use the WordPress design system and public components." The exception was accepted by the product owner. | Stylelint: no raw colour, px spacing or radius values in plugin CSS; component maps in `screens/`; the handle is the one described under Browsers in `screens/README.md`. | `[U]` |
| C5 | The artboard editor is a custom composition named `artboard-editor`. Do not mount, wrap or restyle the post editor or the site editor. | Stated requirement. WordPress for Writers does the same from public parts. | Allowlist excludes `@wordpress/edit-post`, `@wordpress/edit-site` and the `Editor` component of `@wordpress/lazy-editor`. | `[U]` `[V]` |
| C6 | Inside an artboard's frame, behaviour is the stock block editor's and nothing else, with one addition: blocks drag from anywhere (D40). No plugin UI, prompts, starters or overlays inside the editing canvas. | "This should work like any editor, not a custom thing." | Review against `screens/`; AC-EDIT group. | `[U]` |
| C7 | The shell keeps the editor's familiar arrangement: header with inserter toggle, undo, redo, list view toggle, block toolbar docked as in the editor's "Top toolbar" mode, a document bar, and the primary action at the right; a left panel; a right settings panel. | "The in-editor experience and the shell need to remain familiar, not reinvented." | Component maps; AC-SHELL group. | `[U]` |
| C8 | Exactly one artboard is Live (in edit) at a time. Chrome (toolbar, inspector, inserter, list view) is one shared set that belongs to the Live artboard. | Performance; many editors must not run at once. | AC-TIER-01, AC-TIER-02. | `[B5]` `[B8]` `[U]` |
| C9 | All artboards live in one document and share one core-data registry. Each mounted editor has its own block-editor sub-registry. No iframe page per editor. | The editor code loads once; an entity edited once updates everywhere it appears. | AC-DATA-01. | `[B4]` `[V]` |
| C10 | An artboard is a reference to a WordPress entity, a position and a device. Block content is never stored on the board. One exception: a browser (D55) is listed, selected and moved as an artboard and references no entity, only an address. | One source of truth. The exception was accepted by the product owner. | AC-DATA-02; schema in `data-model.md`; AC-BROWSER-05 for the exception. | `[B3]` |
| C11 | An artboard's kind (page, template, template part, pattern) is chosen before the artboard exists and never changes. | "I can't create a post and then change it into a pattern." | No UI path changes kind; AC-NEW-05. | `[U]` |
| C12 | Artboards have one of three devices: Desktop, Tablet, Mobile. No other widths and no free resizing. One exception: the height of a browser's window is resized freely by dragging its bottom edge (D56); its width is its device's. | "We design for surfaces, so only widths sanctioned by Gutenberg." The exception was accepted by the product owner. | AC-DEV group; AC-BROWSER-06 for the exception. | `[U]` |
| C13 | Templates and template parts have no draft state. Saving one changes the live site. Review changes is the only path to saving. One exception: the unsaved content of templates and parts is kept on the server for the preview of the user who has it unsaved (D57), for a limited time; it is used only to draw that user's own preview requests and never reaches the live site. | WordPress has no draft copy for them; Review is the safeguard. The exception was accepted by the product owner. | AC-SAVE group; AC-BROWSER-08 and AC-BROWSER-09 for the exception. | `[U]` `[B8]` |
| C14 | Global styles compile once per change and the result is shared by every mounted artboard. No artboard has its own style override. | Performance. Comparing variations was cut for this reason. | AC-STYLE-03. | `[B7]` `[U]` |
| C15 | The Styles panel is shown in the right panel when nothing is selected, and nowhere else. | "Styles should be when nothing is selected. That is a good UX." | AC-STYLE-01. | `[U]` |
| C16 | Token use counts and usage highlights come from the usage index (parsed block markup and global styles), never from querying rendered artboards. | Ghost and Snapshot artboards are not mounted. | AC-INDEX group. | `[U]` |
| C17 | Inserter lists show names and usage lines only. No rendered previews. | Previews would compete with the Preview tier budget. | AC-INS-06. | `[U]` |
| C18 | Editing happens at 30% zoom or more. Preview tier at 20% zoom or more. Snapshot below 20%. | Decided thresholds. Manual testing showed that editing only at 100% does not work for designers. The stock block tools are placed correctly at other zooms only with the structure and CSS in `spike-report.md`, "Editing below 100%". | AC-TIER group, AC-EDIT-09. | `[U]` |
| C19 | Only users with `edit_theme_options` can open the plugin. Every board is visible to all of them. | One rule, no partial states. | AC-PERM group. | `[U]` |
| C20 | Requires WordPress 7.2 or later. Works without the Gutenberg plugin. | Locked default. | Activation test on clean WordPress. | `[U]` |
| C21 | Pointer, trackpad and keyboard, and on the canvas area the touch gestures of D64. No other touch gesture. | Touch was cut, then asked for on the board so that it can be used on a tablet. | AC-CANVAS-08 to AC-CANVAS-11. | `[U]` |
| C22 | Pan and zoom gestures cause no React render. They change one CSS transform. React state updates when the gesture settles. | Performance. | AC-PERF-01, AC-PERF-04. | `[B5]` `[B6]` |
| C23 | Every user-facing string goes through `@wordpress/i18n` with the text domain `wordpress-for-designers`. | WordPress convention. | ESLint `@wordpress/i18n-text-domain`. | `[N]` |
| C24 | Controls are real buttons, links and inputs with accessible names. Every icon-only control has a label. The board is fully operable by keyboard using the map in `architecture.md`. One exception: resizing a browser's window (D56) is done with the pointer only and has no keyboard equivalent. | Design system rule and decided keyboard set. The exception was accepted by the product owner. | AC-A11Y group. | `[U]` `[D:Main]` |
| C25 | No runtime dependency outside the allowlist. No state library, canvas library or screenshot library. | "Invent nothing"; the concept app's stack (Zustand, Vite) is not carried over. | `package.json` review; C1 lint. | `[U]` `[N]` |
| C26 | The agent surface follows every constraint above. It imports only what `api-allowlist.md` names, adds no dependency, and changes site content only through the functions and stores the UI's own controls use. It sends no REST request of its own to change content. | The reasons of C1 and C25; a change made another way would not show as the designer's does (D73). | C1 lint over `src/agent/`; AC-TOOL group. | `[U]` |
| C27 | The surface costs nothing until an agent is there. On a site where no way in has ever been used (D94) the board sends no request to the relay. The surface's code is a chunk of its own, requested only when a session is found or `window.wfdAgent.ready()` is called. | The largest architectural risk named for this work is bloating the plugin for a feature most sites will not use. | AC-AGENT-01, AC-AGENT-02. | `[U]` |
| C28 | No tool saves, publishes, deletes, trashes or resets anything on the site, takes over a lock, or acts on the Review drawer's checkboxes or Save. | C13: Review is the only path to saving, and it is the designer's (D78). | `agent/tools.md` holds no such tool; AC-TOOL-20. | `[U]` |
| C29 | The agent changes blocks only in the Live artboard, through that editor's own block-editor registry. | C8, D70. | AC-TOOL-08, AC-TOOL-09. | `[U]` |
| C30 | Every tool is one entry of `includes/agent-tools.json` and one function. A tool takes a JSON object, returns a JSON value in one piece, and depends on nothing of the relay: not on a call's id, not on the queue. | D74: the same tools must serve a WebMCP layer and any other way in. | AC-CLI-01; a tool test calls each tool through `window.wfdAgent` with no relay. | `[U]` |
| C31 | Input checks, authorship and marks happen where the tool runs. A change made through `window.wfdAgent` is checked, attributed and marked exactly as one made through `wp wfd`. | D73: showing a change must not depend on which way in was used. | AC-MARK-06. | `[U]` |
| C32 | Nothing in the main plugin names a harness or holds code for one. An adapter is a separate plugin that uses `window.wfdAgent` and the hooks and functions of `agent/surface.md`, For adapters, and holds no tools. The three abilities of D96 are the one exception. | D66, D67. | No string or identifier of a harness in `src/` or `includes/`; the adapter specs under `adapters/`. | `[U]` |
| C33 | The relay's routes require `edit_theme_options` (C19). Its records hold calls and results only, expire, and are deleted on uninstall. | The queue must not become a second store of site content, or outlive its use. | AC-AGENT-07, AC-AGENT-08. | `[U]` `[N]` |
